# GitHub Profile README Refresh — Design

**Date:** 2026-07-13  
**Repo:** `bharat1999/bharat1999` (GitHub profile README)  
**Status:** Spec updated — awaiting final user review before implementation plan

## Problem

1. Profile `README.md` still describes an outdated student / MERN-era bio and does not match `Bharat_Malik_Resume_Updated.pdf`.
2. GitHub stats SVGs use `https://github-readme-stats.vercel.app`, which returns `503 DEPLOYMENT_PAUSED`, so cards do not render.
3. Stats markup is invalid (`<summary>` without wrapping `<details>`).

## Goals

- Rewrite the profile README from the current resume (Senior Software Engineer, full-stack + AI exploration).
- Replace live third-party stats URLs with **static SVGs generated by GitHub Actions** (option B).
- Show an **animated contribution graph (snake)** plus one additional Action-generated animation (3D contrib).
- Keep contact links; add personal site. Keep profile-view counter.

## Non-goals

- Self-hosting or community mirror endpoints
- Embedding the resume PDF in the README
- Private-repo stats (would need a PAT); public stats via `GITHUB_TOKEN` only
- Portfolio website changes outside this profile repo

## README structure

Order of sections:

1. **Welcome / intro** — name, Senior Software Engineer | Full-Stack | 3+ years; one short paragraph from resume summary (React.js, Next.js, Node.js, TypeScript, Nest.js; end-to-end ownership; exploring agentic AI, RAG, LangGraph).
2. **Currently / collaborate / ask-me** — brief bullet list (exploring AI systems; open to interesting web/AI projects; ask about full-stack or AI tooling).
3. **Tech stack** — reflect resume skills (Languages, Frontend, Backend, AI/ML). Prefer simple badge row or compact markdown list; avoid outdated “Mongo | Express | React | Node | Firebase” as the primary framing.
4. **GitHub stats & graphs** — titled section below the intro:
   - Stats + top-langs cards
   - Snake contribution animation
   - Animated 3D contribution calendar
5. **Contact** — LinkedIn (`linkedin.com/in/bharat1999`), email (`bharatmalik1999@gmail.com`), site (`bharatmalik.cv`), profile views badge.

Tone: professional, concise, first-person. Light emoji OK if consistent with existing profile style; do not clutter. Cap animations at the two Action-generated graphs below (no extra third-party typing SVGs or trophy hosts).

## Stats & graph generation (GitHub Actions)

Prefer **one combined workflow** so a single daily run regenerates cards + animations and commits once.

### Workflow

- File: `.github/workflows/update-readme-stats.yml`
- Triggers: `schedule` (daily cron, e.g. `0 0 * * *`) and `workflow_dispatch`
- Job permissions: `contents: write`
- Steps:
  1. `actions/checkout` (current major, e.g. `@v5` / `@v6`)
  2. Generate stats card with `stats-organization/github-readme-stats-action@v2`
  3. Generate top-langs card with the same action
  4. Generate snake SVGs with `Platane/snk/svg-only@v3` (SVG-only for faster runs)
  5. Generate 3D contrib SVGs with `yoshi389111/github-profile-3d-contrib@0.7.1` (or latest stable pin)
  6. Commit and push all generated assets (`|| exit 0` / commit-if-changed pattern)

### Card & graph outputs

| Asset              | Path | Notes |
|--------------------|------|-------|
| stats              | `profile/stats.svg` | `username=bharat1999&show_icons=true&theme=tokyonight` |
| top-langs          | `profile/top-langs.svg` | `username=bharat1999&theme=tokyonight&layout=compact` |
| snake (light)      | `profile/github-snake.svg` | `Platane/snk`, default palette |
| snake (dark)       | `profile/github-snake-dark.svg` | `?palette=github-dark` |
| 3D contrib (embed) | `profile-3d-contrib/profile-green-animate.svg` | Primary animated 3D graph shown in README |

- Token: `${{ secrets.GITHUB_TOKEN }}` (public stats / contributions only).
- README embeds (centered):
  - `![Stats](./profile/stats.svg)` and `![Top Languages](./profile/top-langs.svg)`
  - Snake via `<picture>` with light/dark sources pointing at `./profile/github-snake.svg` and `./profile/github-snake-dark.svg`
  - `![GitHub 3D Contributions](./profile-3d-contrib/profile-green-animate.svg)`
- Wrap cards + graphs in a valid `<details><summary>GitHub Stats</summary>…</details>` **or** a clearly titled open section (details preferred to keep the profile scannable).

### Animation choices (why these two)

| Animation | Action | Why |
|-----------|--------|-----|
| Contribution snake | `Platane/snk` | User choice A; classic contribution-grid animation; Action-generated static SVG |
| 3D contribution calendar | `yoshi389111/github-profile-3d-contrib` | Popular second animation; also Action-generated; no external host |

Explicitly **not** adding: Maeul/CRT/typing-svg/trophy mirrors — they either duplicate the same contribution story or reintroduce third-party uptime risk.

### Bootstrap note

Until the workflow runs once, generated SVG paths may be missing. After merge, user should run **Actions → Update README stats → Run workflow** once so assets appear. README may ship pointing at the paths above before the first run.

## Error handling / reliability

- Broken third-party host is avoided by design (static files in-repo).
- Workflow commit step must not fail the job when there is nothing to commit.
- If Action fails (API rate limit), existing SVGs remain until the next successful run.
